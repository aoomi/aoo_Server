# 现行框架并发与无限等待审计（2026-09-09）

## 审计范围与结论

本次覆盖全部现代服务模块，重点核验当前本地部署链路的 Gateway、Hall、Account、Version、Social、Gifting、Room Authority、GameCommon、GameSPI、Poker 公共运行层，并补查 Matchmaking、Media、ExternalIntegration、Share、LuckDraw、IdentityVerification、Referral、Inventory、Club 与 AdminApi 的同步 HTTP、调度器和等待边界；客户端覆盖公共网络、重连、异步资源加载和呈现协调器。现行链路的检查项已全部关闭；未部署的 `gameServer`、`LegacyAccountServer`、`LegacyCommon` 与 `AooKernel` 仅分类留档，未改玩法和亲友圈业务。

| 范围 | 状态 | 结论 |
|---|---|---|
| Gateway 事件循环与代理 | 已修 | 上游 HTTP 改为异步发送，响应回到 Channel executor，慢上游不再占满 8 个 authority worker。 |
| Room Authority 调度器 | 已修 | 租约续期与房间生命周期拆为两个独立单线程调度器，生命周期慢任务不能饿死租约续期。 |
| Account / 房间顺序锁 | 已修 | 两处无界 `lock()` 改为可中断的 5 秒 `tryLock`，超时明确失败并可靠释放引用。 |
| 数据库连接与读取 | 已修 | 公共 MySQL DataSource 缺省注入 `connectTimeout=5000`、`socketTimeout=15000`，显式配置保持不变。 |
| 客户端原始 HTTP | 已修 | 唯一原始 HTTP 入口统一 15 秒超时，并与调用方取消信号组合；兼容不支持 `AbortSignal.timeout/any` 的运行时。 |
| 客户端资源与 Bundle | 已修 | 公共 AssetLoader 与 FormManager Bundle 单飞缓存增加 15 秒边界；迟到回调不再污染引用或永久缓存僵死 Promise。 |
| Hall / Gifting / Account 内部 HTTP | 已查 | 连接和请求均有明确超时，重试次数有上限。 |
| 其余现代服务 HTTP | 已查 | Matchmaking、Media、ExternalIntegration、Share、LuckDraw、IdentityVerification、Referral、Inventory、Club、AdminApi 均同时具备连接与请求上限。 |
| Version / Social 与现代业务模块 | 已查 | 未发现无界显式锁、同池 Future 等待或无限循环；数据库统一受公共 DataSource 网络边界保护。 |
| Future、事件循环、重试、忙等、分页、事件因果 | 已查 | LOCK01～LOCK12 与 LOOP07～LOOP16 门禁通过。 |
| 未部署旧服务 | 仅旧代码 | LOCK03 留档 64 个无界锁点，全部位于当前未部署的旧 `gameServer`、Legacy 与 AooKernel 路径，不计入现行部署通过结论。 |
