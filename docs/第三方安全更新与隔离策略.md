# 第三方安全更新与隔离策略

## 1. 活动依赖

- 活动第三方能力只通过根 Maven dependencyManagement/BOM 管理，叶子模块不得锁定另一版本。
- 传输栈由 server/Gateway 和受控 Netty BOM 承担；基础运行能力由 server/AooKernel 源码及 SLF4J/Logback 承担。
- 收到高危通告后 24 小时内完成影响判断，72 小时内给出升级、隔离或缓解方案；中低危进入下一维护窗口。
- 升级必须经过依赖收敛、编译、协议、房间主链、重连及回放回归。

## 2. 历史构件

- reference/legacy-2.22/third-party-maven-repository 仅用于差异与历史格式对照，被 .releaseignore 排除。
- 历史 kernel 与定制 Nettosphere 不接收运行补丁，也不得恢复到 POM、仓库或类路径。
- 若必须恢复某项能力，应在当前源码模块重新实现并使用当前受管依赖，不得直接激活历史二进制。

## 3. 证据

scripts/audit-third04-security-path.rb 生成安全维护映射并强制检查活动替代、版本集中管理、历史不可达和发布隔离。
