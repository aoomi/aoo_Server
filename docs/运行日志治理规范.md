# Aoo 运行日志治理规范

## 边界

- `logs/` 与 `server/logs/` 只允许保存本机运行诊断，禁止进入源码、制品、镜像或发布包。
- 应用必须通过部署环境提供日志目录，不得把仓库目录作为生产持久化位置。
- 日志正文禁止记录密码、Token、Cookie、身份证号、私钥、完整手机号、完整请求体、暗牌、牌墙或随机种子。
- 业务关联只记录脱敏后的 `traceId`、`requestId`、`roomId`、`roundNo` 和内部会话摘要。

## 生命周期

- 日志必须按类型分级，至少区分普通运行日志、异常/故障日志和受保护日志。普通运行日志按天且按大小切割、压缩，本机默认保留 7 天后自动清理；“每天自动处理”是每日轮转与清理已过期日志，不得把尚在保留期内的当天或前一天日志全部删除。
- 异常、错误、崩溃、重连风暴、服务降级和故障处置日志必须实时采集到集中日志系统或对象存储，集中保留 60 天；业务节点本机只保留最近 7～14 天的压缩副本。上传成功并通过完整性校验后，本机副本才允许进入空间回收队列。
- 登录安全、管理员操作、权限变更、封禁解封、配置发布、积分、支付、账务、结算和数据修订属于受保护日志或不可变流水，不得跟随普通日志清理。本机只保留运行所需短期副本，权威审计存储默认至少保留 180 天；法律、财务或业务制度要求更长时服从更长期限，并具备防篡改、访问审计和法律保留暂停删除能力。
- 单文件默认上限 100 MiB；每个服务、日志类型和节点必须分别设置每日写入量、目录总量和速率配额。达到上限时轮转、采样或限速并告警，禁止单个异常循环、堆栈或高频请求无限写满磁盘；限速不得吞掉受保护事件本身，可聚合重复事件并保留首次、末次和计数。
- 生产日志必须由外部采集器接管，保留期、访问权限、加密、完整性校验与删除审计由统一策略下发，不得依赖仓库内文件，也不得要求业务服务器本机保存 60 天全量日志。

## 磁盘水位保护

- 固定生命周期清理是日常机制，磁盘水位清理只是紧急兜底，两者必须同时启用。不得只等待磁盘不足 10% 才开始清理，也不得因已有每日清理而省略磁盘监控。
- 以日志所在文件系统的可用空间比例为准：低于 20% 触发容量预警；低于 15% 自动提前清理已过期普通日志、临时日志以及已成功上传并校验的最旧普通日志副本；低于 10% 进入紧急保护，停止非必要 Debug/采样日志，按“普通日志 → 已上传且仍有远端权威副本的异常日志”顺序回收最旧文件，并持续告警和执行扩容/迁移 Runbook。
- 未成功上传或完整性校验失败的异常日志，以及安全、审计、积分、支付、账务、结算和法律保留中的日志，任何磁盘水位都不得由通用清理脚本删除。空间继续恶化时应停止接收新流量、保护核心写入、扩容或迁移日志，而不是破坏证据和账务链。
- 清理任务必须单实例或具备分布式互斥，使用配置的精确日志根目录和文件清单；拒绝空路径、根目录、仓库目录、路径穿越、目录外文件、硬链接/软链接逃逸和仍在写入的活动文件。清理采用有限批次并设置单次删除量与执行时长，避免扫描或删除阻塞业务磁盘。
- 每次自动动作必须记录策略版本、节点、触发水位、候选与实际删除类型、文件数量、释放空间、上传校验状态、跳过的受保护文件、失败原因和执行 `traceId`；清理记录写入独立审计通道，不能与被清理目录同生共死。
- 磁盘采集或集中日志系统不可用时按失败安全处理：不得假定上传成功，不得扩大删除范围；必须告警并进入容量保护。阈值、保留期和配额由配置中心按环境管理，修改需要权限、版本、审批/二次确认、灰度、回滚和审计，业务代码与脚本不得硬编码另一套值。

## 门禁

- `.gitignore` 必须排除根日志与模块日志目录。
- 发布清单、容器上下文和 Maven 资源不得引用这两个目录。
- `scripts/audit-hygiene01-root-logs.rb` 对目录容量、文件大小、敏感赋值和发布引用进行自动检查；只输出命中类别与位置，不复制敏感值。
- 发布前必须验证按天/大小轮转、7 天普通日志清理、异常日志上传与 60 天策略、受保护日志至少 180 天策略、重复日志限速，以及 20%/15%/10% 三档水位动作。故障注入至少覆盖上传失败、磁盘指标失效、并发清理、活动文件、软链接逃逸、异常日志风暴、受保护日志误入候选和清理中断恢复；没有生产等价验证证据不得判定日志治理闭环。
