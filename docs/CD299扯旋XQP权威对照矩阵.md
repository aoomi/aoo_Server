## 3. 下注与阶段矩阵

XQP 下注类型固定为：`NONE=0`、`DROP=1`、`FOLLOW=2`、`REST=3`、`RAISE=4`、`ALL_IN=5`。

| 动作/阶段 | XQP 权威条件与结果 | Aoo 当前差异 |
| --- | --- | --- |
| 预下注 | 非当前行动者可设预休/预跟；轮到时再次校验，失效则恢复人工操作 | 无预下注 |
| 丢 | 当前行动者可丢；退出后续轮转和比牌，但已下注进入结算 | 有动作名，下注与结算规则不等价 |
| 跟 | 补到当前轮有效最大注；余额不足拒绝或转全下 | 简化为固定 `max(amount,mangoScore)` |
| 休 | 首轮开关、上一有效动作和三花状态共同决定可用性 | 仅动作名，无约束 |
| 加 | 有比较玩家时至少达到其门槛的 2 倍；还受本人本轮下注和余额约束 | 仅检查 `amount>=openingBet` |
| 全下 | 使用全部余额；多人时存在 2 倍门槛限制 | 仅检查 `amount>=openingBet`，未使用权威余额 |
| 补牌 | 下注轮结束后统一补牌；前 3 轮回到下注，第 4 张后进入分牌 | 当前按玩家逐个补牌，阶段模型不同 |
| 分牌 | 三花自动分牌；其他有效未丢玩家独立提交；全员完成后亮牌 | 已有提交动作，但无独立倒计时/延时/自动分牌闭环 |

## 4. 结算触发与芒池

XQP `checkOver()` 的结果码直接决定后续状态：

- `-1`：本轮未结束，通知下一位下注。
- `0`：补牌后进入下一下注轮。
- `1`：仅剩一个有效玩家，直接结算。
- `2`：揍芒，芒池累积并升芒后结算。
- `3`：休芒，退还下注、芒池累积并升芒后结算。
- `4`：下注完成且已到分牌轮，进入分牌。
- `5`：未启用休芒时全员休/全下，退还下注并结算。
- `10`：保留的补牌过渡路径。

普通亮牌结算以尾牌优先、尾相同时再比头；尾赢家从芒池领取的额度受本局最大下注与个人下注上限约束。三花退还下注。弃牌玩家与正常比牌玩家的输赢分配分支不同。芒池未领取部分跨局保留。Aoo 当前 `Cd299SettlementEngine` 每局把所有芒果直接作为本局零和分配，无法表达跨局芒池，必须重写而非补丁修正。
