# Aoo 运维恢复演练手册

## 权限与账号

- 发布、数据库迁移、密钥读取、回滚和恢复必须使用彼此独立的短期角色；禁止个人长期管理员账号。
- 密钥只从部署平台注入，不写入命令、仓库、日志或演练证据。
- 所有操作记录操作者、审批单、`traceId`、开始/结束时间及制品摘要。

## 发布前

1. 使用 `./mvnw verify` 构建当前提交并固定制品摘要。
2. 使用 `tools/verify_fresh_migrations.sh` 在空库验证增量迁移。
3. 核对 `deploy/production-services.yaml` 的端口、探针、资源和外部设施。
4. 备份 MySQL、MongoDB、Redis 权威键及配置快照，并执行恢复可读性抽检。

## 启动与健康

1. 顺序启动外部设施、账号服、大厅服、玩法服。
2. 账号服检查 `/health`；大厅、NJPDK、CDXZMJ 检查部署清单中的 TCP 就绪端口。
3. 验证登录、建房、加入、准备、权威操作、重连、解散、结算和战绩读取。

## 回滚与恢复

1. 停止流量并记录最后权威事件序号，不直接删除或覆盖数据。
2. 回滚到已签名制品和匹配配置；只执行已验证的向前修复迁移，禁止未经演练的 DDL 回滚。
3. 从备份恢复后运行完整性检查、事件/快照对账和玩家视角重放校验。
4. 恢复流量前验证幂等键、单端会话、账务流水和房间状态连续性。

## 预发演练证据

必须保存命令、操作者角色、脱敏输出、制品摘要、数据库备份摘要、RTO/RPO、故障注入结果、恢复后业务测试和回滚判定。未具备真实预发环境证据时不得宣称演练完成。
