# 本地核心服务启动

首次配置：将 `config/local-dev.env.example` 复制为 `work/local-runtime/local-dev.env`，填写本机 MySQL 密码。该文件被 Git 忽略。

```bash
./tools/local-dev-services.sh start
./tools/local-dev-services.sh status
./tools/local-dev-services.sh stop
```

`start` 会依次启动或检查正式本地 MySQL、执行 Flyway、写入仅限本地的权威玩法发布/路由数据，构建并启动 Version `8095`、Account `8096`、Hall `8093`、Gateway `8080` 及其仅回环可用的 Room Authority `18080`，最后执行健康检查。NJPDK 等玩法由 Bootstrap 打包的正式 `GameProvider` 提供，不再启动旧 `LegacyGameHall` 或独立旧游戏端口。PID 位于 `work/local-runtime/core-services`，日志位于 `logs/local-dev`。

## 创建房间规则自动同步

本地服务同时托管 `room-rules` 监听进程。用户保存只读人工源 `开房规则表/跑得快/成都跑得快开房规则表.xlsx` 后，监听器会等待文件大小、修改时间和 SHA-256 连续稳定，再验证 xlsx 容器及七列业务约束，随后按“确定性生成 -> 原子替换生成物 -> 事务发布数据库”的唯一链路自动生效。相同哈希不会重复发布，并发发布会被单飞锁拒绝；校验或数据库失败时保留上一 ACTIVE 版本，具体原因写入 `logs/local-dev/room-rules.log`。

```bash
# 查看监听进程和核心服务健康状态
./tools/local-dev-services.sh status

# 单次人工诊断，不作为日常同步入口
./tools/publish-room-rules.sh check
./tools/publish-room-rules.sh preview
```

生产环境不会启动文件监听器。生产发布必须由受控部署流程显式执行 `./tools/publish-room-rules.sh production --play-version <版本>`，并提供独立数据库凭据；因此任意文件写入不能绕过校验直接修改生产数据库。

该入口不会注册开机启动，也不会影响生产自动拉起。重启机器后再次执行 `start` 即可复现；正常停止使用 `stop`。
