# 短回放码迁移链阻塞修复与验证报告（2026-09-07）

## 范围与结论

本次只处理服务端 Flyway 迁移链。未修改客户端、短回放码业务实现、JJMJ、生产数据或 CDP 1234。

空库完整迁移原先在 `V20260826.07` 第 28 行失败。修复后，MySQL 8.0.46 隔离库已从第一条迁移完整执行到 `V20260907.01`，第二次执行为 no-op，外键无孤儿，短回放码目标唯一约束生效，隔离库已清理。

## 根因与历史兼容判断

- `V20260824.01` 创建 `aoo_game_catalog`、`aoo_game_region` 及外键，但只写入类别、玩法族和地区基础数据，没有写入 `game_id=629` 或 `game_id=8`。
- `game_id=629` 只存在于 `database/local/seed_local_runtime.sql` 和既有运行环境数据；它不是正式 Flyway 前置数据。
- `V20260825.97`、`V20260826.01` 与 `V20260826.06` 对 629 的处理均是基于父行存在的条件式 `SELECT`/`UPDATE`，不会在空库创建父行。
- `V20260826.07` 直接插入 `(629,'CN-51-10')` 到 `aoo_game_region`，因此空库触发 `fk_game_region_game`。
- 后续 `V20260826.08` 同样直接为 `game_id=8` 创建地区、发布与索引子行，所以一并补齐该正式发布链的父目录、初始地区和玩法版本前置数据。
- `aoo_login_local.flyway_schema_history` 表明 `V20260826.07` 已于 2026-08-26 成功登记，Flyway checksum 为 `1063645517`。因此没有编辑任何已登记历史迁移；该文件当前 SHA-256 仍为 `7c3017c2a7aeaaf5bbaea8ef3fde07761ba77be1b28fcaefb50fe95c7b74619e`。

## 修复策略

新增 `V20260825_96_1__required_pdk_catalog_prerequisites.sql`，排序在首次 NJPDK 发布 `V20260825.97` 之前：

- 仅当主键不存在时补齐 629 与 8 的目录父行；已有管理数据不被覆盖。
- 使用当时已经存在的 `POKER_UNCLASSIFIED`，由既有 `V20260826.06` 再迁移到 `poker:pao-de-kuai`，保持原顺序职责。
- 补齐既有发布迁移所依赖的初始 `aoo_game_region` 与 `aoo_play_version`。
- 不使用 `INSERT IGNORE` 或关闭外键；若 `game_code`/`provider_key` 与其他主键冲突，唯一约束仍会令迁移失败。
- 新迁移 SHA-256：`5131c8e555f5940ac04d9ba293fc867156905544014271e23a212058e0a854d9`。

由于纠正迁移的版本早于已登记的 `V20260826.07`，正式 Java 启动入口和命令行入口均显式启用 Flyway `outOfOrder`。这使已有环境能够把该迁移作为迟到迁移补登，而不修改或 repair 任何历史 checksum。`audit-dbreal12-flyway-authority.rb` 已增加双入口一致性门禁。

发布运维安全点：所有共享环境均成功补登 `20260825.96.1` 后，可以另行新增变更关闭 `outOfOrder`；在完成环境盘点前不可提前关闭，否则尚未补登的环境会再次出现已解析但未应用的迁移。
