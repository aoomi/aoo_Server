# 回放视角迁移规范

## 1. 安全红线

- 全房间共享回放只能记录所有玩家均可见的公开事件。
- 单座位定向消息、暗牌、牌墙、随机种子、内部状态禁止写入共享回放。
- 禁止读取共享回放后由客户端隐藏敏感字段。

## 2. 当前安全处理

- `playBack2All`：发送并记录公开事件。
- `playBack2Pos`：仅向目标座位发送，不写入共享回放。
- 普通玩家只能读取自己参与牌局且已授权的回放。

## 3. 完整迁移目标

每局生成两类数据：

1. `public-events`：全员可见的公开事件流，只存一份。
2. `private-events/{playerId}`：按玩家分别保存其本人可见的私有增量。

回放响应由服务端按观看者身份合并：

`public-events + private-events/{viewerPlayerId}`

管理员完整审计回放必须使用独立接口、独立权限和审计日志，不得复用玩家接口。

## 4. 强制接口规则

- 回放请求必须携带 `roomId`、`playbackId`，观看者身份从服务端会话取得。
- 服务端校验观看者是否为该局参与者，不接受客户端传入的可信 `viewerPlayerId`。
- 重连快照、观战数据和回放数据必须共用同一套玩家视角裁剪器。
- 新玩法未接入视角裁剪器时禁止发布。

## 5. 验收条件

- 抓取任意普通玩家全部 HTTP/WSS 报文，均不存在其他玩家暗牌。
- 修改 H5、替换客户端或直接调用接口，仍无法取得越权数据。
- 回放、重连、观战分别覆盖本人、他人、管理员和无权限用户测试。
- 日志不记录暗牌明文和完整私有报文。
