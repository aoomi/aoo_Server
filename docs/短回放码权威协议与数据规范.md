# 短回放码权威协议与数据规范

## 权威边界

短回放码的唯一权威入口是 Hall V2 `RecordReplayQueryService` 所使用的 `(room_id,set_id)` 小局回放。生成器不得读取、截断或散列旧 `playBackCode`；旧 11 位码仅由兼容解析器查询 `PlayerPlayBack`，返回明确的 `LEGACY_11` 类型。

`replay_short_code` 是码到小局的唯一映射。主键保证码唯一，`UNIQUE(room_id,set_id)` 保证幂等；竞争写通过数据库唯一约束判定为码冲突或目标已分配，前者重试，后者返回既有码。已分配码永久稳定，不因号码池扩位改变。当前生命周期为永久保留、`ACTIVE`、不自动复用；`expires_at` 仅为未来策略预留，启用前必须先发布保留期与用户提示。

## 码长、容量和冲突

- 码为首位非零的纯数字，依次使用 6、7、8 位；容量分别为 900,000、9,000,000、90,000,000。
- 当前安全阈值默认 70%，配置为 `AOO_REPLAY_CODE_CAPACITY_THRESHOLD` 或 JVM 属性 `aoo.replay.code.capacity-threshold`。
- 达到当前长度阈值，或本长度随机冲突达到重试上限，继续尝试下一长度。每长度默认重试 32 次，可由 `AOO_REPLAY_CODE_RETRIES_PER_LENGTH` 或 `aoo.replay.code.retries-per-length` 配置。
- 8 位也耗尽时返回 `REPLAY_CODE_CONFLICT_EXHAUSTED`，禁止覆盖、回收或回退双写。

## 协议

`GET /api/v2/hall/replay-codes/resolve?lookupType=REPLAY_CODE&value=...` 接收 6、7、8 或 11 位纯数字。响应必须含 `type`：`SHORT` 同时返回 `roomId + setId`，客户端直达该小局；`LEGACY_11` 返回旧兼容目标，客户端随后进入隔离的旧回放读取链。客户端不得自行猜测响应类型。

`GET /api/v2/hall/replay-codes/current?roomId=...&setId=...` 仅向小局参与者或已经用短码取得访问授权的账号返回当前稳定短码。结算提交生成 manifest 后立即幂等分配；该接口兼作异常恢复，不形成第二套写入逻辑。

协议中的 `setId` 与 `perspective_replay_event`、`replay_set_manifest` 一致，按零开始计数；结算域的 `roundNo` 按一开始计数，因此第 N 局必须映射为 `setId=N-1`，禁止把二者直接混用。

用户 ID 与短码长度可能重叠，所以所有查询必须显式携带 `lookupType`。`PLAYER_ID` 接受首位非零、至少 5 位的纯数字字符串，未来自然增长且不设固定最大位数；解析层不得先转为整数或施加回放码长度限制。`PLAYER_ID` 不得被映射成某个小局，也不得通过长度落入 `REPLAY_CODE`。当前只允许账号查询自己的战绩，其他玩家返回权限错误；未来开放关系授权时仍必须逐对象鉴权。

错误码包括 `REPLAY_CODE_FORMAT_INVALID`、`PLAYER_ID_FORMAT_INVALID`、`REPLAY_CODE_NOT_FOUND`、`REPLAY_CODE_EXPIRED`、`REPLAY_CODE_CONFLICT_EXHAUSTED`、`REPLAY_CODE_ACCESS_DENIED`、`REPLAY_NOT_READY` 和 `REPLAY_LOOKUP_TYPE_INVALID`。请求由客户端单飞门禁防重复提交；服务端依靠目标唯一键保持最终幂等。

## 分享、安全与监控

短码是低熵分享凭证。解析要求登录，成功解析才在 `replay_short_code_access` 留下账号授权。原参与者回放时保持自己的事件视角；非参与者凭短码回放时，服务端按 `seat_id,player_id` 升序选择一个确定的原始参与者作为只读回放视角，并只返回公共事件和该单一视角的私有快照。客户端不能指定或切换视角，也不能取得其他座位的私有流。该授权只用于已经结束并形成 manifest 的小局回放，不扩展历史列表、实时牌局或其他房间权限。边缘层应按账号、IP、设备对不存在码查询限速并监控枚举行为。

至少监控：各长度已分配数/容量比、分配冲突次数、重试耗尽数、解析成功率、未找到/权限/未生成/过期错误数、旧 11 位命中量、从结算完成到有码的延迟。6 位接近 60% 时预警，达到配置阈值自动扩 7 位；7 位同理扩 8 位。

## 迁移与回滚

正式迁移为 `V20260907_01__stable_short_replay_code.sql`，只新增映射及访问授权表，不修改旧 `PlayerPlayBack.playBackCode`。发布顺序为迁移、服务端、客户端；回滚客户端和服务端时保留两张表及已分配码，禁止删除或重分配。存量 manifest 在参与者首次请求 `current` 时走同一个幂等分配服务补齐，不进行从旧码截断的 SQL 回填。

测试只能使用任务隔离 schema、测试房间和测试账号。完成后精确删除这些 fixture；不得清理永久生产映射。
