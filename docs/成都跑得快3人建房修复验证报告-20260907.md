# 成都跑得快 3 人建房修复验证报告（2026-09-07）

## 结论

成都跑得快 3 人建房已修复并通过真实 Cocos Canvas 桌面端、移动端和三账号联机验证。3 人玩法使用 48 张牌，每人 16 张、无底牌，牌堆恰好包含 3 张 A 和 1 张 2；2 人玩法仍使用 40 张牌，每人 16 张、8 张底牌，同样包含 3 张 A 和 1 张 2。桌面端与移动端提交的 3 人规则完全一致，不存在 User-Agent 分支。

## 根因与修复

原始界面默认勾选 `remove_three_four`。服务端 `PdkGameProvider.create` 因此把成都规则识别成仅允许 2 人的 `CUT_40` 配置，再用 3 个座位校验该配置，抛出 `IllegalStateException: player count outside rule snapshot`。

修复分两层：

- 客户端 `CreateRoomRulePresenter` 在初始化及人数切换后统一协调依赖；选择 3 人时移除仅适用于 2 人的 `remove_three_four`。
- 服务端 `PokerCatalogRuntimeRegistry` 在创建成都 3 人房时执行权威防御：强制 `STANDARD_48` 并移除外部 `deckCards`，再从有效规则建立配置和玩法族。即使旧客户端仍提交 `remove_three_four`，3 人房也不会被错误映射为 40 张牌。

规则表 `Client/docs/开房规则表/跑得快/成都跑得快.xlsx` 的“人数”行恢复为 `单选 / 2人｜3人 / 默认第1项 / 三端显示`；发布器校验为 7 个字段，`sourceHash=868990270cc863b4da6d2130e1c4dec833fa556f1b6d26dd180c5531afff5fc8`。
