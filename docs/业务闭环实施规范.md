# Aoo 棋牌业务闭环实施规范

## 1. 强制原则

1. 生产环境的会话、幂等、账务、房间快照、Outbox、回放不得使用内存实现。
2. 所有写操作必须具有稳定 `requestId` 或业务唯一号，并由数据库唯一约束兜底。
3. 所有房间下行必须经过玩家视角投影；禁止广播完整房间对象后由前端隐藏。
4. 房间创建时锁定全部规则、流程、算分、房间和 UI 配置版本，牌局中不可改变。
5. 管理后台只操作配置和业务命令，不允许直接修改生产数据库。

## 2. 实施顺序

| 顺序 | 闭环 | 上线门槛 |
|---|---|---|
| 1 | Redis 会话 | 多节点登录、刷新、踢线、重启恢复通过 |
| 2 | 百万亲友圈 | 游标分页、按圈索引、在线定向分批推送通过 |
| 3 | 房间账务结算 | 创建、扣费、退款、结算、战绩可幂等及每日对账 |
| 4 | 防暗牌泄露 | 普通、重连、观战、回放四种视角安全测试通过 |
| 5 | 明确业务协议 | 关键操作不再依赖通用 dispatch 解释语义 |
| 6 | 配置发布 | 全国玩法动态合并，地区不复制配置 |
| 7 | 权限中心 | 玩家端和管理后台使用相同权限代码 |
| 8 | 运营治理 | 申诉、生命周期、维护、灰度和回滚形成闭环 |

## 3. 会话闭环

- Access Token 短期有效，Refresh Token 只能使用一次并轮换。
- Redis 权威键包含 `userId/sessionId/deviceId/sessionVersion`；禁止依赖 Java 进程内 `accountMap`。
- 登录、改密、封禁、退出和新设备登录必须撤销旧会话并断开 WSS。
- `wsTicket` 有效期不超过 30 秒、一次使用、绑定会话和设备。

## 4. 百万亲友圈

- 成员按 `clubId` 分片，列表只允许游标分页，单页最多 200。
- 全员通知先查询在线成员索引，每批最多 1000；不得扫描全服成员对象。
- 每名接收者生成独立不可变 DTO，禁止循环修改同一消息对象。
- 圈主、管理员建立独立索引；搜索使用专用检索库或数据库索引。

## 5. 房间、账务与结算

- 创建房间：幂等占位 -> 冻结费用 -> 创建房间 -> 写事件 -> 确认流水 -> Outbox。
- 失败通过撤销冻结或补偿任务恢复，不做内存回滚。
- 扣费唯一号：`room:{roomId}:player:{playerId}:consume`。
- 退款唯一号：`room:{roomId}:player:{playerId}:refund`。
- 小结算唯一号：`round:{roomId}:{roundNo}:{settlementVersion}`。
- 大结算唯一号：`final:{roomId}:{settlementVersion}`。
- 每日对账房间、扣费、退款、局数、结算、战绩和 MQ 事件，差异生成异常工单。

## 6. 视角和回放

- 玩家仅收到自己的暗牌，其他玩家只显示牌数和公开牌。
- 观战默认不显示任何暗牌；延迟观战也必须使用独立策略。
- 重连返回该玩家权威快照和缺失事件，不返回完整房间状态。
- 普通回放按玩家视角裁剪；完整回放仅限授权人员并记录查询原因。

## 7. 全国玩法发布

后台只保存一条 `NATIONAL` 配置，不向省市复制。大厅查询某省市时依次合并全国、省、市配置；相同 `gameId` 由更具体地区覆盖。发布生成不可变版本，房间只引用版本快照。

## 8. 权限和运营

- 标准权限：成员查看/管理、创建/解散房间、财务查看/调整、规则发布、完整回放查看。
- 客服只能创建申诉和补偿单，不能直接修改余额、积分或战绩。
- 玩法支持停止新建、存量完成、维护、灰度、地区、亲友圈白名单、最低客户端和服务路由版本。
- 账号、聊天、回放、战绩、账务分别配置热存、归档、销毁和法务冻结周期。

## 9. 已落地持久化基线

- `JdbcBillingService` 是统一资产变更入口，数据库余额行锁与 `businessId` 唯一约束共同保证幂等。
- `JdbcSettlementRepository` 保存不可变大小结算；同一业务号再次提交不同结果必须拒绝。
- `JdbcRoomSnapshotStore` 同时拒绝事件序号回退和 fencing token 回退，旧节点不得覆盖新节点状态。
- `aoo_room_event` 使用 `(room_id,event_sequence,visibility,owner_player_id)` 复合主键，同一权威动作可同时保存公共事件和各玩家私有事件。
- `JdbcClubMemberIndex` 是规模化亲友圈公共目录，列表只允许游标分页；指定玩家通知直接按明确 ID 发送，不伪装成受众查询。
- 账号登录按 `db_player.account_id` 点查，V15 强制建立 `idx_db_player_account`；禁止在千万账号规模下无索引扫描。
- 上述能力全部进入 `ProductionPersistenceAssembly` 快速失败门禁，生产环境不得替换为内存实现。
