# 玩家视角回放规范

## 安全边界

- 回放观看者身份只能从服务端登录会话取得，客户端传入的玩家编号无效。
- 普通玩家必须是该局参与者，只能读取公开事件和自己的私有事件。
- 禁止向普通玩家返回其他玩家手牌、暗牌、牌墙、随机种子和内部状态。
- 管理员完整回放必须使用独立后台接口、独立权限和审计日志，不得复用玩家接口。

## 查询协议

- 正式消息：`replay.perspective_page`。
- 请求字段：`roomId`、`setId`、`afterSequence`、`limit`。
- `limit` 默认 200、最大 500；使用序号游标，不允许深分页。
- 响应按 `sequence` 排序，返回 `items`、`nextSequence`、`hasMore`。
- `payload` 保留原始 JSON 字符串，客户端只按对应 `messageId` 的协议模型解析。

## 写入与可用性

- 牌局线程只写有界异步队列，数据库短时故障不得阻塞牌局。
- 队列积压、写入失败和丢弃数量必须接入监控告警。
- `(roomId,setId,sequence,visibility,ownerPlayerId)` 是幂等键，重试不得产生重复事件。

## 数据留存

- 留存天数由管理后台按合规要求配置，不允许写死在业务代码中。
- 定时任务调用 `ReplayRetentionService` 分批清理，每批最多 5000 条。
- 先清理过期事件，再清理无事件引用的参与者授权记录。
- 涉及申诉、风控或司法冻结的牌局，清理任务必须先排除冻结清单。
