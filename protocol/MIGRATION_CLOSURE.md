# 协议迁移收口与旧协议退役

## 当前状态

- V2 代码迁移、服务端权威校验、玩家视角裁剪和正式重连接口已经落地。
- 旧接口已标记弃用但暂不删除，用于线上客户端平滑升级和紧急回滚。
- “代码完成”不等于“生产退役完成”；生产退役必须满足观察条件。

## 旧协议流量观察

- Redis 键：`aoo:protocol:legacy-usage:YYYY-MM-DD:endpoint`。
- 仅记录接口每日调用次数，不记录玩家信息、令牌、请求参数和牌局数据。
- 计数保留40天，退役判断窗口为连续30天。
- 任意旧接口在窗口内出现调用，观察期从该接口最后一次调用后的次日重新计算。

## 删除旧接口的全部前置条件

- 所有旧协议接口连续30天调用量为零。
- 不存在使用V1协议创建或运行中的房间。
- 支持V1的最低客户端版本已经被强制升级或停止登录。
- V2重连、结算、登录、亲友圈和子游戏端到端回归通过。
- 已完成一次V2回滚演练，并确认数据版本可以前后兼容。
- 线上错误率、重连成功率和消息乱序指标达到发布阈值。

## 退役顺序

1. 管理后台停止向新客户端下发V1能力。
2. 网关拒绝创建新的V1房间，但允许已有V1房间完成。
3. 等待所有V1房间自然结束并确认房间数为零。
4. 保持旧接口代码一个完整观察窗口，只告警不接入新业务。
5. 完成回滚演练后关闭V1路由。
6. 下一发布周期再删除旧处理器、DTO和兼容映射。

## 禁止事项

- 禁止仅因代码迁移完成就把M8标记为完成。
- 禁止在仍有活动房间时删除旧协议。
- 禁止通过客户端上报判断协议流量，必须使用网关或服务端计数。
- 禁止把旧回放数据直接作为玩家增量事件下发。
